# pre 新增功能回归（2026-10-23）

## 范围

对比 `main` 的 `324c8b7` 与 `pre` 的 `4fe13ee`：12 个新增提交、78 个文件，覆盖第三方导入、周课表、课程配色、系统日历同步、小组件、通知设置及官网预览工作流。修复在本地 pre 工作区，并包含此前安全加固的未提交改动；没有提交、推送、部署或合并 main。

## 发现并修复的问题

| 功能 | 触发与影响 | 修复 |
| --- | --- | --- |
| 系统日历增量同步 | 普通 App 无权写入 Calendar Provider 的 `SYNC_DATA1`；读取失败被视为空表；重复 UID 和撤销记录可能导致重复、误清理 | 用 description 中独立 UID 标记，兼容读取旧标记；查询失败显式报错；批事务完成后记录撤销；重复 UID 收敛为一条 |
| 日历事件形态变更 | 单次事件与重复事件互转时遗留 `DTEND`、`DURATION` 或 `RRULE`；清理一个日历可能覆盖另一个日历的撤销记录 | 显式清理互斥字段；按目标日历限制清理范围和同步记录 |
| ICS | 源时区与 App 时区不同、夏令时、UTC 跨日、精确 UNTIL/EXDATE、COUNT 较大时展开错误；VALARM 字段污染事件 | 在源时区展开后转换，精确处理次数与边界、支持 DURATION，跳过嵌套提醒；无效和不支持的规则明确报错 |
| WakeUp 课程包 | 正式五行课程包无法正确关联课程名及真实作息 | 按五段结构读取，通过 `(id, tableId)` 关联课程及详情，保留真实时间；继续兼容简化 JSON/ZIP，保留安全限额 |
| 时间线 | App 时间与系统时间混用，红线与课表使用的日期/时区不一致 | 统一共享时钟与 App 时区，当前周启用后按秒刷新，支持秒级位置计算 |
| 横滑切周 | 相邻页额外位移使时间列残影进入当前页 | 移除多余横向变换，保留轻微缩放与淡入淡出；保留纵向滚动和课程点击 |
| 横屏课表 | 时间列高度不足，时间文字挤压或被截断 | 最小节次高度计入标题、两行时间及字号；不足时滚动，标题单行自适应 |
| 第三方导入面板 | 横屏或放大字号时底部入口超出可视高度且无法滚动 | 面板内容独立纵向滚动，保留三个导入入口和原有卡片结构 |
| 赶课提醒 | 下一节已经与当前课程重叠，仍安排下课前赶课通知 | 排除这种已开始的重叠课程对 |
| 通知子开关 | 关闭考试或换楼提醒没有立即重排，已排闹钟发送时不重新检查，导致关闭后仍通知 | 设置变化立即重排；发送前再次检查总开关与对应子开关，避免旧闹钟越过关闭状态 |
| 课程胶囊 | 仅比较时钟，次日相同时间误触发“即将上课”，开课后标签不准确 | 按完整日期时间区分下一节、进行中与课前 10 分钟警示，补齐中英繁文案 |
| 胶囊紧凑显示与警示颜色 | 1×1/2×1 宽度下状态标签挤掉课程时间；Android 11 的警示文字变白但背景未切换 | 窄尺寸分行显示状态、课程与时间地点；使用所有支持版本可用的圆角警示背景和深红文字，状态变化后恢复普通配色 |
| 深色胶囊标签 | 标签保留浅色底，却采用深色主题的浅色文字，导致“下一节课”“上课中”不易辨认 | 标签按其实际浅色背景选择强调文字，对比度低于 4.5 时回退；空状态同步修正，并在真实 RemoteViews 中检查对比度 |
| 备忘录小组件 | 旧系统不能滚动；最多截取 60 行，后续笔记无法访问 | 所有支持版本统一按需服务列表，移除行数截断；每行携带自身笔记信息，保留完成与编辑入口 |
| 小组件背景 | 调背景透明度导致文字一起淡出；旧 Android 深色模式出现白字浅底、透明度无效，且不支持的 RemoteViews 调用导致加载失败 | 独立背景层处理颜色和透明度，文字始终不透明；只在支持的系统重置视图 alpha，旧系统用背景颜色 alpha；深浅切换显式恢复卡片和列表文字配色 |
| 设置重置与配色 | 重置遗漏新增开关；课程 ID 含 `=` 或 `;` 时保存配色丢失 | 补齐用户和小组件重置键；配色采用 JSON，兼容读取旧格式 |
| Netlify 清理顺序 | GitHub 状态接口失败会跳过旧预览物理清理 | 顺序调整为校验新网址、清理旧 pre 部署、报告状态；保留生产、当前与其他分支保护 |
| pre 预览触发条件 | 仅修改 Android 文件再推 pre 不触发预览，因此没有该提交的新网址 | 移除路径过滤，每次 pre 推送均触发；保留分支限制和串行部署 |

## 启动复验与保留观察项

最新 Debug 与 Release APK 在 API 30 的 `am start -W` 均返回 `Status: ok`、`LaunchState: COLD`，已查看实际课表/首次启动声明截图；当次 crash buffer 为空。

API 34 新增功能的仪器测试通过，但最终冷启动复验**未计为通过**：旧 AVD 弹出 System UI 无响应，系统设置启动也超时；日志同时存在 Google Play 服务、System UI 和其他系统进程的 ANR，模拟器 GPU 后端还出现显示上下文创建失败。禁用快照、改用软件渲染后仍有系统超时。另建未安装课简的全新 AVD，首次系统初始化也耗时约 216 秒；安装本次 APK 后 Release 的启动等待超时，截图抓取也超时，未完成新环境的 Debug 启动复验。

旧 AVD 还曾记录课简 Debug 后台任务 `No response to onStartJob` 的 ANR，其调用栈未完整捕获，且同一时间段多个系统进程也发生 ANR。现有证据无法确定该记录是否来自应用缺陷，不将其直接判定为 pre 新增问题，也不宣称已经排除。相关 ANR、超时、截图及环境日志全部留档；需要在稳定的 API 34 环境或实体设备上继续确认启动与后台任务。

## 边界与未验证范围

- ICS 支持本项目课程模型可表示的事件和 WEEKLY 重复；全天、跨午夜及 RDATE/EXRULE/RECURRENCE-ID 等不支持的形式会明确拒绝，不能称为完整 RFC 5545 实现。
- 导入器的格式、时区、异常输入和模型映射有自动测试；未使用真实学校账号逐校验收，WakeUp 历史变体与 AISchedule 第三方规则仍可能有差异。
- 通知时间计算有 JVM 回归；未穷举各厂商后台策略、勿扰模式或真实过夜送达。系统日历权限拒绝时不能同步，不自动提升权限。
- 未实际运行远端 GitHub Actions、Netlify 部署或删除操作；工作流验证限于静态检查、URL 样例及清理脚本测试。
- 已确认 main 同样存在窄屏放大字号时英文课程详情“Cancel once”文案裁切，以及官网 Hero 下载按钮在附加体积信息下的文案裁切。本轮记录为既存问题，未扩大到无关页面重设计。
- 未验证折叠屏折叠过程及实体设备启动器差异。测试结果只代表已执行的环境与用例。
