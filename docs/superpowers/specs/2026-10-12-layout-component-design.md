# 布局组件与侧边栏自定义 设计

日期：2026-10-12　状态：待用户确认（审阅已过一轮）

## 为什么做

侧边栏放的东西越来越多（主体页面、组件、快捷按钮），常用页面要先点菜单再找。用户想要一种「常用页面在底栏一点即达、其余收进二级菜单」的布局，又不想丢掉现在的侧边栏；同时希望以后还能加别的布局，而且布局这件事整个放在一个公开组件里，主体只出通用能力。

## 目标

1. 课简主体自带「设置 → 侧边栏」：侧边栏各项可排序、可开关；关掉的项收进侧边栏底部「更多」，仍能打开。不装任何组件也能用。
2. 主体新增通用的「布局」能力（组件 API 12）：组件声明自己提供布局，并通过页面命令把选定的布局交给主体；主体用原生 Compose 画出来。
3. 新建公开组件仓库（暂名 `cursimple/cursimple-layout-component`，组件名「布局」）：在组件设置页里切换「侧边栏 / 底边栏」，并选择底栏放什么。
4. 随时切回侧边栏，不用重启；组件停用或删除时自动回到侧边栏。

## 非目标

- 这次不做底栏以外的新布局（平板竖栏、顶部标签页等），只把扩展点留好。
- 不改各页面自身内容（课表、笔记等页面内部布局不动）。
- 不做自绘悬浮层、不用 WebView 画导航栏。

## 反目标（做出来也算失败的情况）

- 主体代码、字符串、类型名里出现这个组件的名字或专属协议。
- 某种配置下「课表」或「设置」再也点不到。
- 组件页面崩了、被删了，课简卡在一个空白或半残的外壳里。
- 切换布局时丢掉用户已有的侧边栏设置、组件侧边栏开关等现有偏好。

## 已经定下的（用户决定）

- 底栏方案 A：默认「课表 · 笔记 · 组件 · 我的」。
- 底栏放什么在组件设置页里自选；「课表」固定第一个，「我的」固定最后，都锁定；中间最多 3 个。
- 没放进底栏的入口全部出现在「我的」里；「设置」在「我的」里，所以永远可达。
- 侧边栏自定义在主体里做，不依赖组件；「课表」「设置」锁定不能关。
- 关掉的入口不是消失，而是进「更多」（侧边栏）或「我的」（底栏）。

## 设计

### 1. 通用导航目的地（主体）

主体维护一份与布局无关的目的地清单，每项有稳定 ID、原生图标和本地化名称，布局只引用 ID：

| ID | 对应 | 可关 |
|---|---|---|
| `schedule` | 课表 | 否 |
| `courses` | 课程 | 是 |
| `memos` | 笔记 | 是 |
| `plugins` | 插件（市场） | 是 |
| `reminders` | 提醒 | 是 |
| `settings` | 设置 | 否 |
| `about` | 关于 | 是 |
| `components` | 组件汇总页（已装组件列表 + 市场入口，复用 `AllExtensionsScreen` 的内容） | 是，仅底栏布局可用 |

快捷操作也有 ID：`action.theme`、`action.background`、`action.overrides`、`action.update`，在侧边栏底部作为一组，在「我的」里作为一行圆形按钮。

这些 ID 是主体的通用词汇，写进 `docs/plugin-system.md`。

### 2. 侧边栏自定义（主体，所有用户都有）

- 新偏好：侧边栏项目顺序（ID 列表）+ 关闭集合 + 快捷按钮组开关。存 DataStore（自动进入备份），编解码放独立文件并有单测，照 `MarketSourcesPreferences.kt` 的做法。缺失或无法识别的 ID 回落默认，新增的 ID 追加到末尾。
- 「设置」里加子页「侧边栏」，按 `SettingsDestination.Plugins` 的模式接入（枚举、标题、搜索项、根页行）。列表可拖动排序（参考 `SettingsQuickDragState`），每行开关；`schedule`、`settings` 显示锁且不能关。快捷按钮组一个开关。
- 侧边栏：按顺序显示开着的项；有被关的项时，在快捷区上方显示描边按钮「更多（n）」，点开 `ModalBottomSheet` 列出被关的项，点了照常进入。组件分区「最多 3 个 + 查看全部」规则不变，不进这个列表。
- 侧边栏设置只管侧边栏：在这里关掉的项，切到底栏后照常出现在「我的」里，也照常能选进底栏（两种布局分开保存，已向用户复述并确认）。
- 关掉快捷按钮组时，四个快捷操作（主题、背景、调课、检查更新）一起进「更多」面板；「我的」页的快捷按钮行不受影响。〔实现者决定〕
- 页面顶部：当前生效的是组件提供的布局时，显示一张提示卡「当前使用组件提供的布局」和描边按钮「换回侧边栏」，文案不写组件名。这是组件页面坏掉时的兜底出口。〔实现者决定〕
- 重置设置时一并恢复默认，并清掉生效的布局记录（回到侧边栏）。〔实现者决定〕

### 3. 布局能力（主体，组件 API 12）

**声明**：`manifest.extension.layouts`，列出组件可能使用的外壳：

```json
"layouts": [{ "id": "bottom-bar", "title": "底边栏", "shell": "bottomBar" }]
```

安装校验与 widgets 相同的位置（`PluginPackageReader.validateKind`）：需要 API ≥ 12，id 唯一且安全，最多 8 项。`PluginApiVersion.CURRENT` 升到 12，新增 `LAYOUT_MIN = 12`。不认识的 `shell` 不拒装（为以后留路），只是不能应用。

**能力探测**：页面的 `CurSimpleComponent.capabilities.layouts` 给出 `{ shells: ["drawer","bottomBar"], destinations: [...上表 ID...], maxBarItems: 5 }`。组件据此决定显示哪些选项，旧主体没有这个字段时组件提示需要更新课简。

**应用**：新页面命令 `layout.apply`：

- `{ shell: "drawer" }`：交还给主体默认侧边栏。
- `{ shell: "bottomBar", items: ["schedule","memos","components"] }`：`items` 是底栏前段，主体自动在最后加「我的」。

主体校验：调用方必须是已启用、声明了 `layouts` 的组件；`shell` 在支持列表里；`items` 首项是 `schedule`、ID 都已知且不重复、总数加「我的」在 3–5 之间（即中间至少 1 个、最多 3 个，符合 M3 底栏 3–5 个入口的规范）。〔实现者决定〕不通过就返回错误，不改当前布局。另有 `layout.current` 返回当前生效的布局和归属组件，供组件设置页回显。

**保存与生效**：生效的布局（归属组件 ID + shell + items）存进 UserPreferences（进备份）。主体启动和每次组件状态变化时判定：归属组件已安装、已启用、兼容、仍声明该 shell，才使用底栏；否则显示侧边栏。停用后再启用会恢复之前的底栏；删除组件时清掉这条记录。从应用内备份恢复出的记录同样走这个判定：组件没装就保持侧边栏，之后装上并启用该组件时自动恢复底栏。注意 user_preferences 只进应用内备份（导出 / WebDAV），不进系统备份。〔实现者决定〕多个布局组件时，最后一次 `layout.apply` 的那个说了算。

### 4. 底栏外壳（主体原生）

- `Scaffold(bottomBar = NavigationBar)`，M3 `NavigationBarItem`，图标用现在侧边栏同一套 `Icons.Rounded`，选中态 primaryContainer 指示条。「我的」上显示更新红点（原来菜单按钮和关于、插件上的红点合并到这里）。
- 不显示 `ModalNavigationDrawer`，左上角不再有菜单按钮，侧边栏手势关闭。
- 「我的」页（新原生页，标题用主体通用字符串「我的」）：顶部卡片（应用名、当前周、版本，有更新时可点）→ 一行快捷圆形按钮 → 列表，按第 1 节表格的固定顺序列出底栏没放的目的地（`components` 排在 `memos` 之后），与侧边栏设置无关。〔实现者决定〕
- 从「我的」进入的页面：顶栏左侧显示返回，返回回到「我的」，底栏仍然可见并选中「我的」。
- 「组件」页：列出已启用、开了「在侧边栏显示」的组件，加一个进入组件市场的按钮；点组件进入其页面，返回回到「组件」。
- 返回键：在非课表标签时回到课表（与现在一致）；子页先回上一层。
- 全屏子页面（学期管理、导入导出等）照旧覆盖整个界面。
- 首次引导中指向菜单按钮的那一步，在底栏模式下改为指向「我的」。
- 嵌入网页的组件页面要正确留出底栏高度（`innerPadding`）。
- 切换时用现有的 200–250ms 过渡，不跳回课表以外的意外页面：切换后停在原来的目的地，若该目的地在新布局里在「我的」下，就显示为从「我的」进入的状态。

### 5. 布局组件（新公开仓库）

照 `cursimple-notify-component` 的结构：`plugin-packages/<id>/manifest.json`、`main.js`（`checkLogin` / `sync` 空实现）、`ui/`、`checksums.json`；`scripts/pack.mjs`、`scripts/preview.mjs`（模拟桥）、`test/`（`node --test`）、`.github/workflows/release.yml`（tag = 版本，产出 ZIP + 带 `filename` 的 `manifest.json`）、README 中英双语、MIT。

- manifest：`kind: extension`，`apiVersion: 12`，`minHostVersion` 为带有 API 12 的课简版本，无网络权限，`extension.layouts` 声明底栏，`ui.entry` 与 `ui.settingsEntry` 都是设置页。
- 设置页（唯一页面）：顶部分段控件「侧边栏 / 底边栏」；底栏实时预览；目的地列表可拖动排序、开关，「课表」「我的」显示锁；中间超过 3 个时新开的项自动挤掉最后一个并提示。改动即调用 `layout.apply`，失败时恢复页面状态并说明原因。选「侧边栏」时提示「侧边栏的内容在课简 设置 → 侧边栏 里调整」。
- 主题读宿主令牌；控件遵循 `docs/ui-guidelines.local.md`（48px 触达、有框按钮、不用原生下拉、深浅色、1.3 倍字号、320px）。图标用 Material Icons Rounded 并附 Apache-2.0 许可。
- 收录：发布后在 `cursimple-components/components.json` 加条目和别名（布局、底栏、底边栏、导航、layout、bottom bar），收录页加三语介绍。

## 留给实现者的

- 具体 Kotlin 类名、文件拆分、`MainActivity` 的拆分程度（建议把外壳选择抽成独立 composable，避免继续膨胀）。
- 拖动排序控件的具体实现，只要满足无障碍（可用按钮上移/下移替代拖动）。
- 组件包 id、版本号起点、预览脚本细节。
- 「组件」页与现有 `AllExtensionsScreen` 的复用方式。

## 验证

- 单测：侧边栏偏好编解码与默认/未知 ID；布局校验（各种非法 items）；生效判定（停用、删除、不兼容、shell 未声明）；manifest `layouts` 校验与 API 门槛。
- Compose 测试：侧边栏关项后出现「更多」并能打开；底栏切换、从「我的」进入后返回、更新红点位置、课表和设置在任何配置下可达。
- 组件：`node --test` 覆盖规则（锁定项、最多 3 个、能力缺失提示），浏览器预览检查浅/深色、320px、1.3 倍字号。
- 模拟器：安装组件、切换、停用、删除、备份恢复后的布局；模拟器屏幕目前是黑的，视觉需真机确认，未验证项会写明。
- 按惯例：本地构建后交 APK 和组件 ZIP，用户真机测过并明确说推，才 commit / push / 发版 / 收录。
